# Property Viewer MVP — Spec

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Build a RAG-powered property search web app that lists, searches, and displays property details with improved UI/UX over youroverseashome.com, deploying on Vercel.

**Architecture:** Next.js 14+ (App Router, TypeScript, Tailwind CSS) frontend + FastAPI (Python) backend wrapping the existing `rag_pipeline.py` RAG system. Frontend communicates with backend via REST API. ChromaDB vector store from existing `properties_data.json`. Deployed on Vercel (frontend + Next.js API routes; FastAPI as a separate serverless function or container).

**Tech Stack:** Next.js 14+ (TypeScript), Tailwind CSS, shadcn/ui components, ChromiumDB (reused from existing POC), FastAPI (Python), Vercel deployment.

---

## Problem Statement

The existing RAG property search system (`rag-property-search-poc`) provides a working vector-search pipeline but lacks a polished, user-facing web interface. Users need to browse properties, search with natural language, filter results, and view property details in a clean, modern UI. The reference site (youroverseashome.com) demonstrates the target UX but needs significant visual improvement.

## Solution

A dual-application architecture:
1. **Frontend:** Next.js app on Vercel with Server Components for initial page load, Client Components for search interactivity. Uses the Stripe design system aesthetic (preserved blue/white/gray color palette from youroverseashome.com) with improved spacing, typography, card layouts, and responsive behavior.
2. **Backend API:** FastAPI wrapper around `rag_pipeline.py` exposing `/search` (natural language query) and `/properties` (list with filters) endpoints. Reuses the existing ChromaDB collection and `properties_data.json` — no rescraping.

## User Stories

1. As a user, I want to see a list of property cards on the homepage so I can browse available properties at a glance.
2. As a user, I want to type a natural language query in a search bar and see relevant properties returned so I can find properties matching my criteria.
3. As a user, I want to see property cards displaying thumbnail, title, location, price, bedrooms, bathrooms, and size so I can compare options quickly.
4. As a user, I want to click a property card and see a detailed page with full description, all specs, and share functionality so I can evaluate the property thoroughly.
5. As a user, I want filter controls (price range, bedrooms, property type, location) so I can narrow results without retyping a query.
6. As a user, I want sort options (recently added, price low-high, price high-low) so I can control how results are ordered.
7. As a user, I want pagination or infinite scroll so I can browse through many results.
8. As a user, I want the site to feel fast and responsive on both desktop and mobile so I can use it on any device.
9. As a developer, I want the frontend and backend to be decoupled so each can be deployed and scaled independently.
10. As a developer, I want the existing RAG pipeline code to be reused without modification so no data rescraping is needed.
11. As a developer, I want the app to deploy to Vercel with a single command so deployment is simple and repeatable.
12. As a developer, I want the app to run locally with `npm run dev` so I can develop and test before deploying.

## Implementation Decisions

- Frontend framework: Next.js 14+ App Router (supports both SSR and client-side interactivity needed for search)
- Styling: Tailwind CSS with shadcn/ui component primitives, styled to match Stripe design tokens but with the blue/white/gray palette from youroverseashome.com
- RAG backend: FastAPI wrapping existing `rag_pipeline.py` — the `search_properties()` and `format_search_results()` functions become API endpoints
- Vector store: ChromaDB PersistentClient, reusing `chroma_db/` directory and `properties_data.json` from existing POC
- No rescraping: the MVP uses existing data only; scraping pipeline is out of scope
- Deployment: Vercel for frontend + Next.js API routes; FastAPI can run as a Cloud Run service or be replaced by Next.js API routes for the MVP scope
- Design system: Stripe-inspired visual language (from popular-web-designs) but with youroverseashome.com's blue color scheme substituted for Stripe's purple

## Testing Decisions

- Frontend: Playwright or Cypress for E2E search flow testing
- API: pytest for FastAPI endpoints using TestClient
- Visual: browser_vision to verify the Stripe-inspired design matches the reference
 No unit tests for MVP scope — E2E and integration tests only

## Out of Scope

- Rescraping property data from websites
- User authentication or accounts
- Favorites/bookmarks functionality
- Multi-country support (MVP is Spain-only, data as-is)
- Advanced filtering beyond price, bedrooms, property type
- Real-time chat or agent interaction
- Analytics or tracking
